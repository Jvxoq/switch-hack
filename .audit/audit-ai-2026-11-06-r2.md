## Findings in rev 2 (all fixed in rev 3)
1. [Serious] Approver came from a tool argument the model fills before the owner clicks, so the `owners` check and the record's
   approver were model guesses. Fix: approver is read from Switch's approval record or marked `switch-approval`; never a tool argument.
2. [Serious] Tripwire's 20-call / 3-minute budget was per incident, so a reopened incident was handed off on its first call.
   Fix: budget per incident and ask round.
3. [Serious] E03 moved `contained → verifying` for cap/fallback actions, but the PATCH transition table did not allow it,
   so those incidents could never resolve. Fix: transition added for non-disabling actions only.
4. [Worth fixing] The hourly-ceiling incident was opened straight in the service: no thread, no alert, nowhere to offer revert.
   Fix: E02 emits a `RuleHit` into `IncidentManager`.
5. [Worth fixing] Detector and Tripwire write the same JSON files at the same time; read-modify-write could lose updates.
   Fix: one lock, one worker, plus a concurrency test.
6. [Worth fixing] Headless Claude Code cannot answer "always ask" prompts, so the eval asserts were unclear.
   Fix: permission-prompt stub records attempts and declines.
7. [Worth fixing] `handed_off` incidents never got a record, though the proposal says every outcome lands in one. Fix: E03 records them.
